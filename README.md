# GitHub Achievement Hunter

A small public repository for learning GitHub collaboration workflows through real, useful changes.

This project is a practice space: the goal is to understand how GitHub collaboration works and to contribute work that would still be useful even if profile achievements did not exist.

## Missions

- [x] Initialize the repository and document its purpose.
- [ ] Complete a focused issue-to-pull-request workflow.
- [ ] Practice merging a pull request without requesting a review (a deliberately labelled YOLO experiment).
- [ ] Collaborate with another developer using a genuine co-authored commit.
- [ ] Host useful GitHub Discussions and receive accepted answers from other participants.
- [ ] Grow the project through useful contributions and organic discovery.

A mission is complete only when the corresponding activity has actually happened and can be checked in the repository or on the relevant GitHub profile. A checklist is a plan, not proof that an achievement was awarded.

## A practical collaboration workflow

1. **Find a real improvement.** Read the existing documentation, reproduce a problem, or discuss a concrete proposal in an issue.
2. **Agree on the scope.** For larger changes, comment on or open an issue so contributors do not duplicate work.
3. **Create a focused branch.** Use a descriptive name such as `docs/clarify-pr-workflow` or `fix/broken-example`.
4. **Make a meaningful change.** Keep the diff focused, preserve existing conventions, and avoid unrelated formatting churn.
5. **Review your own diff.** Check spelling, links, rendered Markdown, and whether the change actually solves the stated problem.
6. **Open a pull request.** Explain the motivation, summarize the changes, link the related issue, and state what you checked.
7. **Respond to feedback.** Discuss review comments and push follow-up commits when needed.
8. **Merge only when appropriate.** Follow repository permissions and branch rules; do not merge merely to complete an achievement checklist.

See [CONTRIBUTING.md](CONTRIBUTING.md) for the detailed contributor checklist.

## Ground rules

This repository is an activity playground, not an achievement generator. GitHub controls achievement eligibility and can change its criteria. The repository cannot guarantee that any action will award an achievement.

- No fake accounts, purchased stars, fabricated co-authorship, self-awarded answers, copied low-effort changes, or spam.
- Every contributor must use their own account and accurately represent their work.
- Co-authorship must reflect a real contribution and must be agreed to by everyone named.
- Do not ask people to create meaningless issues, reviews, discussions, or reactions just to trigger profile activity.
- Keep experiments clearly labelled and do not bypass repository protections.

Some activities require independent participation from other people. Those missions remain open until genuine collaboration or community participation occurs.

## Achievement status

- Quickdraw: reported as earned by the repository owner; verify on the owner's GitHub profile.
- Pull Shark: reported as earned by the repository owner; verify on the owner's GitHub profile.
- Other achievements: check the relevant GitHub profile and GitHub's current eligibility rules after completing eligible activity.

Status notes in this repository are informational. They are not proof of an award, and contributors should not claim an achievement until it appears on the relevant profile.
